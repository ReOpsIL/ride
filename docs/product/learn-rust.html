Ride · Learn

Rust for people who already code. One Python developer, one real script, two weeks.

The learner

Maya writes Python every day. She wants Rust in her toolbox.

She is a data engineer. Her pipeline has one slow script that sums a sales CSV by region. She has read the first chapters of the Rust Book twice. Every time she opens a real file, the compiler says no and she does not know why. This deck follows her for two weeks, porting that script inside Ride.

Ownership

b = a stops meaning two names

In Python both names point at one list. In Rust the value moves to b, and a is gone.

Borrowing

Read or write, not both at once

Appending to a list while looping over it is legal Python. Rust refuses it before the program runs.

Strings

Two string types

String owns its text. &str is a view into text someone else owns. Python has one str.

Errors

No try / except

A function that can fail says so in its type, Result. The ? operator passes the error up.

Types

Types everywhere, mostly inferred

She rarely writes them, but they are always there. She needs to see them without typing them.

Traits

No duck typing

"Has a len" is not enough. A type implements a trait, and the compiler checks it.

Ride's bet: teach these six on the code Maya is already writing. The compiler is the teacher, the IDE translates, and Maya types every fix herself.

The same error, explained five ways

E0382 borrow of moved value: `rows`

  • Python. b = a gives one list two names. Here the list was handed to the function, and rows no longer holds anything.
  • JavaScript. Like passing an array, except the caller's variable is emptied afterwards.
  • Go. A slice would share its backing array. A Rust Vec has exactly one owner.
  • Java. No garbage collector keeps both references alive. The owner frees the value, so there can be only one.
  • C++. Every pass by value is an implicit std::move, and the compiler forbids use after move.

The comparisons are data, one short file per language and per error code, next to the cheat sheets. They are reviewed text, not generated on the fly.

Coach E0502 · Borrowing

cannot borrow `*prices` as mutable because it is also borrowed as immutable

The rule. Many readers, or one writer. Never both at the same time.

If you know Python
Changing a list while looping over it is a classic Python bug. The loop sees the new items. Rust turns that bug into a compile error.
Step 1 · Questionopen
Can you finish reading before you start writing?
Where this leads
Collect the new prices first, then add them in one go:
let extra: Vec<f64> = prices.iter()
    .filter(|p| **p > 100.0)
    .map(|p| p * 0.9).collect();
prices.extend(extra);

Result and ?

No exceptions. Every place that can fail is marked.

Maya's loader reads a file and parses numbers. Both can fail. In Python that is invisible until it raises. In Rust the signature says it, and each ? is a spot where the function can stop and hand the error up.

Lesson card Result and ?

? is a raise you can see. If the file is missing, line 2 returns the error to the caller. If a number is bad, line 6 does.

If you know Python
float(cols[2]) can raise ValueError, but nothing on the line tells you. Here the ? does, and the caller must handle the Result.

Plan

Most of the engine is already here. The teaching layer is new.

Learn is a mode of Ride, not a separate app. It reuses the compiler data, the oracle, the debugger and the cheat sheets, and adds a thin layer of explanation on top.

In the tree today
  • Cheat sheets. 89 Rust topics, about 2,000 templates with keys and docs, chosen by caret context.
  • Compiler data. Live cargo check and clippy JSON, with every span and label.
  • Types. rust-analyzer hover, Type Info and type-aware completion.
  • Debugger. lldb-dap with frames, locals and Rust formatters.
  • Tests. Tests panel, gutter markers, Rerun Failed.
  • AI. Chat panel, Explain and engine context packs.
  • Structure. tree-sitter items and the reference index, which can tell what was written.
To build
  • Ownership overlay. Draw rustc's labels on the lines, numbered in order.
  • Coach and hint ladder. Cards for the top 15 borrow and type errors, per source language.
  • From Python keys. A Python field and section in the cheat sheet data.
  • Type lens. Inlay hints, oracle card O-4.
  • Learning mode. Ghost text off, tutor prompt, simple menus, local model.
  • Concept tracking. Detect concepts from the syntax tree and fixed errors, stored locally.
  • Tracks. Four projects with checkpoint tests, plus Rustlings.
  • X-ray. Drop marks and a heap view. The largest card, so it comes last.
