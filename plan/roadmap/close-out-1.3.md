## DS-1 Data-safety fixes — Tier B

Three audit defects from `todo/app/remaining.md` (2026-09-17). One root cause: the editor has one incremental edit path (`RideTextView.replaceText(in:with:)` → `shouldChangeTextIn` records `document.pending` → `textDidChange` shifts folds and underlines and registers undo) and three consumers that bypass it or are not shifted by it.

**Read first.** `app/Ride/Editor/EditorCoordinator.swift` (`textDidChange`, lines 32–60), `app/Ride/Editor/RangeShift.swift`, `app/Ride/Editor/Underlines.swift` (`shift`), `app/Ride/Editor/EditorHostView+Jump.swift` (`replaceText(_:)`), `app/Ride/Editor/RideTextView+Edit.swift`, `app/Ride/Editor/PendingDelivery.swift` (`apply`, `deliver`, `refreshView`), `app/Ride/Debug/Breakpoints.swift`, `app/Ride/Debug/AppState+Breakpoints.swift`, `app/Ride/Engine/SessionService+Paint.swift` (`mergeHighlights`), `app/Ride/Engine/SessionService.swift` (`attach`, line 42 `restyle`), `app/Ride/Editor/EditBuild.swift`.

**(1) Breakpoints shift with edits.** `BreakpointMark.line` is absolute and nothing updates it. Add a pure `app/Ride/Debug/BreakpointShift.swift`:
- `struct LineEdit { let firstLine: Int; let lastLine: Int; let newLastLine: Int }` built by `static func lineEdit(before: String, range: NSRange, inserted: String) -> LineEdit` — `firstLine` is the 1-based line of `range.location` in `before`, `lastLine` the line of `NSMaxRange(range)`, `newLastLine = firstLine + newlines in inserted`. Count newlines by scanning UTF-16 units of `before` up to the offsets (no `LineIndex`, keep it pure).
- `extension Breakpoints { mutating func shift(path: String, edit: LineEdit) -> Bool }` — a mark on line `L`: `L <= firstLine` unchanged; `L > lastLine` becomes `L + (newLastLine - lastLine)`; `firstLine < L <= lastLine` removed (its line was replaced). Returns whether anything changed. Reuse `normalized` for dedupe and order.
- Hook in `EditorCoordinator.textDidChange` next to `Underlines.shift`: build the `LineEdit` from `pending.before`, `pending.range`, `pending.inserted`; when `DebugController.shared.breakpoints.shift(path:edit:)` returns true call `state.breakpointsChanged(path:)` (which re-sends to the debugger, refreshes gutters and schedules the workspace save). Path is `document.fileURL?.standardizedFileURL.path` exactly as `caretBreakpoint` computes it.
- Tests `app/RideTests/BreakpointShiftTests.swift`: insert a line above shifts by +1; delete two lines above shifts by −2; an edit on the breakpoint's own line keeps it; deleting the lines containing a mark removes it; a same-line replacement without newlines changes nothing and returns false. Register `BreakpointShift.swift` and the test file in the RideTests Sources phase (`Breakpoints.swift` is already there).

**(2) Whole-text replacement is undoable and minimal.** `EditorHostView.replaceText(_:)` calls `undoManager.removeAllActions()` then `textView.string = text`, so Reformat Document, Reload and Replace in Project cannot be undone and skip every shift. Replace the body: compute the minimal edit between the current `textView.string` and `text` with a new pure `app/Ride/Editor/TextDiff.swift` — `static func minimalEdit(from old: String, to new: String) -> (range: NSRange, text: String)?` over UTF-16 units (common prefix, common suffix not overlapping the prefix, never splitting a surrogate pair; `nil` when equal) — then apply it through `textView.replaceText(in:with:)`. Keep `lines.invalidate()`, `syncGutter()`, `updateCurrentLineHighlight()`. Remove `removeAllActions()`. Because the edit now flows through `textDidChange`, folds, underlines, breakpoints (1) and highlights (3) shift, the engine gets an incremental edit, and ⌘Z restores the pre-format text as one step (wrap in `beginUndoGrouping`/`endUndoGrouping`). `PendingDelivery.apply` still sets `document.text` first and still calls `SessionService.shared.resync` afterwards; leave both. Tests `app/RideTests/TextDiffTests.swift`: identical → nil; pure append; pure delete in the middle; replacement in the middle; a change touching a surrogate pair widens to whole scalars; the reformat case (indent change on line 3 of 5 leaves lines 1–2 and 4–5 out of the range).

**(3) Highlights shift with edits.** `document.highlights` keeps engine byte offsets; `mergeHighlights` invalidates only the ranges the engine reports as changed, so on re-attach `HighlightApply.restyle` paints stale offsets. Add a pure `app/Ride/Editor/ByteSpanShift.swift`: `protocol ByteSpan { var startByte: UInt32 { get }; var endByte: UInt32 { get } }` and `static func shifted<S: ByteSpan>(_ spans: [S], start: UInt32, oldEnd: UInt32, newEnd: UInt32, rebuild: (S, UInt32, UInt32) -> S) -> [S]` — spans ending at or before `start` unchanged, spans starting at or after `oldEnd` moved by `newEnd - oldEnd`, spans overlapping the edit dropped (the engine repaints the changed range). Conform the generated `HighlightSpan` in an app-side extension (not in the test target) and call it from `textDidChange` right after `EditBuild.make` with the edit's byte offsets. Tests `app/RideTests/ByteSpanShiftTests.swift` with a local struct conforming to `ByteSpan`.

**Gates.** No engine change: `xcodebuild … build test` (the three new test files green) and the Rust self-test on a fresh copy of `samples/rust-demo`, `EXIT 0`, zero `^FAIL`. Add one self-test step at the END of the Rust array: set a breakpoint on line 10, insert a line above it through `insertText`, assert the mark is now on line 11 and `state.debug.breakpoints.lines(path:)` agrees, then undo and assert it is back on 10. Files under ~200 LOC, no comments, no force-unwraps.

## 1.3-6b Introduce Constant and Inline Variable — Tier B

**Introduce Constant (⌥⌘C).** `Engine::introduce_constant(session_id, start_byte, end_byte) -> Option<ExtractPlan>` in `src/refactor/constant.rs`. ## 1.3-5a Fix-its in diagnostics — Tier A (engine only)

Intention actions need the compiler's own suggestions. Today the cargo parser (`src/check/message.rs`, `parse.rs`) drops `children` and `suggested_replacement`, and the clang command (`src/check/clang.rs`) does not pass `-fdiagnostics-parseable-fixits`.

- `src/ffi/check.rs`: `Diagnostic` gains `fixes: Vec<DiagnosticFix>` with `#[derive(uniffi::Record)] pub struct DiagnosticFix { pub title: String, pub edits: Vec<TextEdit> }`. `TextEdit.caret_byte` is the end of the last edit.
- Cargo: `message.rs` adds `children: Vec<CompilerMessage>` (default) and `Span` gains `suggested_replacement: Option<String>`, `suggestion_applicability: Option<String>`. In `parse.rs`, for each primary-span diagnostic collect a `DiagnosticFix` per child message that has at least one span with `suggested_replacement`, `title` = the child's `message`, one `TextEdit` per such span (`byte_start..byte_end` → replacement) in the same file as the diagnostic, only when `suggestion_applicability` is `MachineApplicable` or `MaybeIncorrect`; `HasPlaceholders` and `Unspecified` are dropped. Spans in other files are dropped from that fix (report a fix only if all its edits landed in the diagnostic's file).
- Clang: add `-fdiagnostics-parseable-fixits` to `DIAG_FLAGS`; in `clang_parse.rs` a `fix-it:"<file>":{l1:c1-l2:c2}:"<text>"` line attaches to the most recent diagnostic whose file matches (the fix-it lines follow their diagnostic), `title` = `Apply fix: <text>` (or `Remove` when text is empty), bytes through `LineOffsets::byte_at`; unescape `\"` and `\\` in the text. Live mode maps `<stdin>` back to the real path as the diagnostics do.
- App compile: `CheckService`/`StoredDiagnostic` gain `fixes: [DiagnosticFix]` carried through `insert`/`replace` unchanged (identity for `ForEach` stays `Hashable`; `TextEdit` is already `Hashable` in the generated bindings, otherwise hash on the title). Nothing displays them yet; the executor only keeps the app building and its tests green.
- Tests: `tests/check.rs` gets a captured cargo JSON line with a `MachineApplicable` child (an unused-import removal and a `use` insertion suggestion) asserting the fix edits; a `HasPlaceholders` child asserts no fix; `tests/clang_check.rs` gets a fixture with a `fix-it:` line asserting the edit range and text, and one with an escaped quote.

Gates: `cargo fmt`, `cargo clippy`, `cargo test`, `scripts/build-engine.sh`, `xcodebuild … build test`.
